# 策略制定总框架

策略 = 全面理解之上的路径选择。本篇是通用框架，攻单场景见 `deal-strategy.md`，存量经营场景见 `account-strategy.md`。

## 输入：四源态势盘点

出策略前把四源信息逐项列出，每项标注**事实 / 推断 / 未知**——未知项转化为下一步动作，不是拍脑袋补齐：

| 信息源 | 要盘什么 | 视角卡 |
|---|---|---|
| 客户侧 | 业务目标与预算、决策链与关键人处境、时间窗、现有绑定 | 客户各角色换位卡 |
| 竞争侧 | 同台者及其节奏、双方优劣、对手的客户关系与打法 | 竞争对标与替换打法 |
| 我方侧 | 产品适配度、案例与标杆、可投入资源、伙伴力量 | 铁三角与扩展角色 |
| 约束侧 | 合规要求、交付能力边界、组织流程、内部资源冲突 | 产品线/服务线视角 |

## 五步框架

1. **态势**：上面的四源盘点，输出"我们处在什么局面"的一段话——写不出来就是理解不够。
2. **目标**：可量化（签单额/份额/消费增量）、有时限、**有底线**（walk-away 条件：低于什么条件不做）。
3. **胜负手**：我方赢面收敛到 **3 个以内**——超过 3 个就不再是胜负手，是愿望清单；每个胜负手要配"怎么放大"，短板配"怎么补或怎么绕"。
4. **路径与节奏**：里程碑节奏（先手动作 / 节奏点 / 收口）、资源编排（谁在什么时间做什么）、依赖前置（资质、POC、高层公关）。
5. **预案**：If-then 表——每个重大风险对应"触发条件 → 动作 → 决策人"，不留"到时候再说"。

## 策略评审（红队质询）

策略上桌前过四问，答不出就回去改：

- 这个策略最大的三个假设是什么？**哪个假设错了策略就崩？**
- **对手如果看到我方策略，会怎么打？**（策略的鲁棒性）
- 哪个动作最容易被拖到不做？**没有节奏点的策略等于没有策略。**
- 把相关角色的视角卡过一遍：**每个关键人会因为这个策略更支持还是更防备我们？**

## 常见策略谬误

| 谬误 | 症状 | 解法 |
|---|---|---|
| 信息幻觉 | 拿推断当事实推进（"客户肯定没预算了"） | 事实/推断/未知标注；未知项定动作 |
| 以产品为中心 | 从产品功能倒推客户需求 | 从客户业务目标正推（需求澄清框架） |
| 单点依赖 | 全押一个支持者，人动则局崩 | 决策链多点布局，Coach 不唯一 |
| 节奏失控 | 被对手或客户时间表拖着走 | 主动设节奏点，每次会后我方先定下一步 |
| 静态策略 | 形势变了策略不更新 | 策略带版本与复审时间，重大事件触发复审 |

## 关键话术

- 没有写下来的策略不存在：一页纸、双签、进作战室，才算策略。
- 策略的第一产出是"不做什么"：资源有限，放弃清单比行动清单更重要。
- 策略不是预测，是应对：预案的价值在触发的瞬间兑现。
