# 安全与合规

## 身份与访问

- **AAA**：认证（Authentication，你是谁）、授权（Authorization，你能做什么）、审计（Accounting，你做了什么）
- **IAM/最小权限（Least Privilege）**：只授完成任务所需的最小权限集；权限膨胀是常态，需要定期回收
- **AK/STS**：长期 AccessKey 泄露是云上头号事故源；**人走 SSO、应用走 RAM 角色、跨端走 STS 临时凭证**（SEC-01）
- **零信任（Zero Trust）**：默认不信任任何网络位置，每次访问都验证身份与上下文；"内网即安全"的替代范式

## 数据保护

- **加密**：**对称加密**（AES，快，用于数据本体）、**非对称加密**（RSA/ECC，慢，用于密钥交换与签名）；传输加密 TLS、静态加密云盘/对象存储
- **KMS 与信封加密**：密钥集中管理、轮换与审计；用 KMS 加密"数据密钥"、数据密钥加密数据，避免明文密钥落盘
- **数据分类分级**：公开/内部/敏感/机密分级，分级决定加密、访问与留存策略——数据治理的起点
- **脱敏（Masking）**：展示与测试环境对敏感字段变形处理（掩码、假名化）

## 边界与应用防护

- **WAF（Web Application Firewall）**：拦截 OWASP 常见攻击（注入、XSS、爬虫）；部署在 LB 前/上
- **DDoS**：**流量型**（带宽洪水，靠高防/清洗中心）与 **CC 型**（应用层资源耗尽，靠限频/人机识别）；防护本质是带宽与算力的军备，方案要写清"谁来清洗"
- **补丁与镜像基线**：定期扫描漏洞、统一安全基线镜像（SEC-05）

## 审计与合规

- **操作审计（ActionTrail/CloudTrail）**：全量 API 调用记录，独立账号集中留存 ≥180 天（等保要求 6 个月起）
- **等保 2.0**：国内合规基线，一至五级，常见系统过**三级**；要求映射到技术措施（双因素认证、审计留存、容灾、加密）
- **合规自动化**：配置审计 + 合规包持续评估，而非人工巡检（对照 cloud-frameworks Landing Zone 合规基线）
- **渗透测试与攻防演练**：定期验证， finding 闭环
