# 可靠性与容灾

## 两个核心指标

| 指标 | 含义 | 决定 |
|---|---|---|
| **RTO**（Recovery Time Objective） | 故障到恢复服务的最长可接受时间 | 容灾方案的成本等级 |
| **RPO**（Recovery Point Objective） | 最多可容忍的数据丢失时长 | 备份/复制的频率与方式 |

先问业务要 RTO/RPO，再选方案——顺序不能反。RPO=0（零丢失）与 RPO=小时级，方案差一个数量级的钱。

## 容灾等级（成本从低到高）

| 等级 | 机制 | RTO/RPO 量级 |
|---|---|---|
| 备份恢复（Backup & Restore） | 定期备份、灾时重建 | 天/小时级 / 小时级 |
| 冷备（Pilot Light） | 数据实时复制，计算资源灾时拉起 | 小时级 / 分钟级 |
| 热备（Warm Standby） | 缩容版双套环境常备，灾时扩容接管 | 分钟级 / 接近 0 |
| 双活/多活（Active-Active） | 多 AZ/多 Region 同时承载 | 接近 0 / 0 |

组合词：**同城双活**（同地域跨 AZ，抗机房级故障）、**两地三中心**（同城双中心 + 异地灾备，金融监管常见要求）、**异地多活**（多地域同时服务，最高成本）。

## 备份

- **3-2-1 原则**：3 份副本、2 种介质、1 份异地
- 定期做**恢复演练**——没验证过的备份不算备份（REL-04）；快照策略按 RPO 定频率
- 数据库备份 + Binlog 结合才能做到时点恢复（PITR）

## 过载与故障隔离

- **限流（Rate Limiting）**：保护自身不被打垮；算法上**令牌桶**（允许突发）/ **漏桶**（恒定速率）
- **熔断（Circuit Breaking）**：下游持续失败时快速失败并周期性探测恢复，防止故障传导与线程堆积
- **降级（Degradation）**：牺牲非核心功能保主链路（关推荐、关评论、保下单支付）
- **隔离（Bulkhead）**：资源池分舱（连接池/线程池/实例分组），单舱故障不倾覆全船
- **超时与重试**：所有跨网络调用必须有超时；重试要配**退避（Backoff）+ 幂等**，否则重试风暴会放大故障

## 故障管理

- **单点故障（SPOF）**：识别方法是"这个组件挂了会发生什么"——答不出或答"全挂"即单点
- **故障演练/混沌工程（Chaos Engineering）**：主动注入故障验证冗余与恢复有效；大促前必做
- **复盘（Postmortem）**：无责复盘文化，产出改进项并跟踪关闭（OPS-05）
