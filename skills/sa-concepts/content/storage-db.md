# 存储与数据库

## 三种存储形态

| 形态 | 接口 | 特征 | 典型场景 |
|---|---|---|---|
| 块存储（Block） | 磁盘挂载 | 低时延，随实例 | 系统盘、数据库盘 |
| 文件存储（File/NAS） | 目录树/NFS | 共享挂载 | 共享目录、AI 训练数据集 |
| 对象存储（Object） | REST API | 容量近无限、按量、不可改写 | 图片视频、备份、数据湖底座 |

对象存储按访问频率分层：标准 → 低频 → 归档/冷归档，**生命周期规则自动沉降**（COST-03）。

## 数据库分类

| 类别 | 代表 | 适合 |
|---|---|---|
| 关系型（RDBMS） | MySQL/PostgreSQL | 事务、强一致、复杂查询 |
| KV | Redis | 缓存、会话、计数 |
| 文档 | MongoDB | 结构多变的半结构化数据 |
| 宽表 | HBase/Cassandra | 海量写入、按行键查询 |
| 时序 | InfluxDB/TDengine | 监控、IoT 指标 |
| 向量 | Milvus/向量引擎 | 语义检索、RAG |
| 分析型（OLAP） | ClickHouse/Doris/StarRocks | 聚合分析、报表 |

**OLTP vs OLAP**：OLTP 高并发小事务（订单、支付），OLAP 大范围扫描聚合（报表、风控分析）。混用一个库是性能问题的经典根源——**分析流量从生产库剥离**（读写分离 → 独立 OLAP）。

## 扩展手段（按代价从低到高）

1. **右型升配**：改规格，分钟级
2. **读写分离（主从复制）**：一主多从，读能力线性扩展；代价是**主从延迟**——写后立即读要强制走主库
3. **分库分表（Sharding）**：按 shard key 水平拆分；跨分片查询与分布式事务是复杂度来源，shard key 选错最难回退
4. **换分布式数据库**：原生分布式（PolarDB-X/TiDB 类），兼容 MySQL 协议降低改造成本

## 缓存

- **旁路缓存（Cache-Aside）**：读先查缓存、未命中回源并回填；写先更库再删缓存——最常用默认模式
- **三大经典问题**：**穿透**（查不存在的 key，用布隆过滤器/空值缓存）、**击穿**（热 key 过期瞬间打穿，用互斥重建/逻辑过期）、**雪崩**（大批 key 同时过期，用随机 TTL）
- **多级缓存**：本地缓存（快但不一致）→ 分布式缓存（一致性好）→ CDN（静态边缘）

## 数据一致性

- **强一致**：写完成立即可见，代价是时延与可用性
- **最终一致**：允许短暂不一致、收敛保证；分布式系统的默认权衡（配合 BASE，见 architecture-principles）
- **幂等（Idempotency）**：同一操作重复执行结果不变；重试、消息消费、支付回调的安全前提，用唯一键/去重表实现
