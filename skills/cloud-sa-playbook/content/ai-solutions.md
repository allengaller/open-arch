# AI / 大模型场景的 SA 打法

AI 是当前云增长最快的商机线，也是历史绑定最弱的竞争窗口。AI 商机对 SA 的要求：既懂模型与算力的技术选型，又能把"想用 AI"翻译成可落地的场景与 ROI。

## 商机分层

| 层 | 客户形态 | 卖什么 | SA 角色 |
|---|---|---|---|
| 算力底座 | 模型公司/科研/大企业自研 | GPU 实例、高性能网络、容器/调度、存储 | 算力选型、训练/推理架构、成本设计 |
| 模型与平台 | 想用大模型能力的企业 | MaaS/API（如通义系模型）、微调与评测、私有化部署 | 模型选型、场景匹配、私有化 vs API 决策 |
| 应用层 | 所有行业客户 | RAG 知识库、Agent 工作流、行业 AI 应用方案 | 场景梳理、方案设计、POC 主导（最高频打法） |

**层级越低越技术，越高越像咨询**：应用层商机的胜负手是场景选择与 ROI 论证，不是模型参数。

## 客户 AI 落地五阶段

    1 试点探索（找场景、小 POC）→ 2 场景验证（单场景跑通出 ROI）
    → 3 平台化（统一模型网关/知识库/评测）→ 4 规模化（多场景复制、组织与流程配套）
    → 5 智能化运营（持续评测、成本治理、模型迭代）

SA 按客户所处阶段定打法：1-2 阶段卖场景与快速见效（POC 2-4 周）；3 阶段卖平台架构（模型网关、向量库、安全护栏）；4-5 阶段卖治理与成本优化（评测体系、算力调度、缓存与量化）。

## 典型方案模式

**RAG 企业知识库**（最常见的落地起点）：文档解析与切分 → 向量化 → 检索增强生成 → 权限与溯源。关键设计：知识更新流水线、权限隔离（RAG 泄密是最大事故源）、答案引用溯源、评测集（准确率/召回率基线）。

**Agent 工作流**：单 Agent（客服/助手）→ 多 Agent 协作（流程自动化）。关键设计：工具调用边界、人工接管点（Human-in-the-loop）、执行审计、失败兜底。生产级 Agent 的难点在可靠性与可观测，不在 Demo。

**微调 vs 提示工程决策树**：优先提示工程 + RAG（成本低迭代快）；领域语言/格式强定制 → 轻量微调（LoRA）；基座能力根本不覆盖 → 大规模微调或换基座。给客户预期管理：微调不解决幻觉，RAG 不解决领域语感，组合拳才是正解。

**私有化 vs 公有云 API 决策**：

| 维度 | 私有化部署 | 公有云 API |
|---|---|---|
| 数据敏感度 | 强监管/涉密/数据不出域 | 可脱敏或非敏感 |
| 成本 | 固定投入高（GPU 闲置风险） | 按量，边际成本低 |
| 迭代速度 | 升级靠自建团队 | 模型持续更新 |
| 适用 | 金融/政府/军工核心 | 大多数企业场景（混合：敏感层数据脱敏后调 API） |

## 算力与推理优化要点（SA 最小知识集）

- 训练 vs 推理资源画像完全不同：训练要高显存互联（多机多卡、RDMA 网络），推理要吞吐/延迟平衡（批处理、KV Cache）。
- 推理优化三板斧：量化（精度换显存与吞吐）、缓存（相同/相似问题命中）、弹性伸缩（业务潮汐）。
- GPU 成本设计：稳态推理包年 + 峰值按量/抢占式；训练任务用弹性调度填谷。
- 常见坑：按峰值常备 GPU（利用率 20% 以下）、忽略存储与网络瓶颈只看卡、没有评测集就上线。

## AI 商机的验证与话术

- **评测先行**：和客户共建评测集（真实业务问题 50-200 条），POC 报告用评测数据说话——AI 效果没有评测集就是玄学，也是扯皮源头。
- **幻觉治理**：RAG + 引用溯源 + 护栏（敏感问题拒答）+ 人工审核点，按场景风险分级设置自动化程度。
- **ROI 难量化时的替代指标**：人工工时替代率、响应时长缩短、覆盖率提升（7×24）、客诉下降——先定基线再上系统。
- **数据安全问答包**（客户必问，提前备好）：数据是否用于训练（不用于，需书面承诺）、驻留地、隔离方案、审计日志。

## 关键话术

- 先找场景再谈模型：客户说"想用大模型"时，SA 的第一任务是陪他挑出 3 个 ROI 可验证的场景。
- 2 周见效的 POC 胜过 2 个月的完美方案：AI 落地拼迭代速度。
- 效果评测集是 AI 单的"成功标准"（衔接 `poc-playbook.md`）：没有它，验收就是吵架。
- AI 是竞争破局点：存量云绑定深，但 AI 场景大家都在同一起跑线。
