# 内部协同与流程纪律（内部情况）

单子赢在客户现场，卡死在内部流程。铁三角的分工见 `iron-triangle.md`，本篇讲流程与协同的纪律：商机、报价、POC 立项、交付、合同、汇报升级、跨部门摩擦。注：具体系统与审批层级随云厂商而异，此处写通行结构（对照包级声明）。

## 1. 商机管理纪律

- **录入及时、阶段如实**：商机进 CRM/系统当天录入；阶段定义按"客户行为"不按"我的感觉"（客户没确认预算就不算验证阶段）
- **别养胖子单**：一个长期不动又舍不得关的单子，占用的不只是 forecast 数字，还有你每周的精力。90 天无进展即降级或关闭
- **Forecast 即军令状**：报上去的数字会被资源排期、备货、政策审批当依据；报"乐观值"透支的是自己的信用
- **丢单必复盘**：输给谁、输在哪一环（关系/方案/价格/时间）、下一家能不能避开，写进复盘记录

## 2. 报价与折扣

- **报价前自查三件事**：客户预算区间摸过没有；竞对价差多少；这一单的竞争/标杆/战略价值够不够支撑申请
- **审批层级与折扣深度成正比**：越深的折扣审批链越长、要的材料越多——别在最后一周才发现要走总部审批
- **特殊折扣要带故事**：纯降价申请最难批；"竞对标杆 + 可公开案例 + 三年承诺"的打包故事最容易过
- **让步换承诺**：政策使用的完整纪律见 `self-playbook.md`

## 3. POC 立项与资源

- **立项在方案前**：POC 资源（云资源、专家、伙伴人力）都是申请来的，先立项后干活，别先干活再补流程
- **成功标准前置书面锁定**：客户签字的验收指标 + 环境 + 时间窗，缺一样都别开跑（执行纪律详见 `poc-playbook.md`）
- **资源有借有还**：POC 结束无论成败，资源释放/转商用二选一——挂着不还的资源会烧掉你下次申请的信用

## 4. 交付协同

- **SA 早于合同介入交付排期**：签约后才开始找交付资源，通常已经晚了 4-6 周
- **自营 vs 伙伴交付的选择**：标杆客户/新技术场景优先自营保质量；规模化复制交给伙伴保毛利——选择本身要和 BD 在签约前对齐
- **验收标准前置进方案**：交付验收标准在售前方案阶段就写清楚，交付阶段再谈验收 = 扯皮开始

## 5. 合同与法务

- **合同评审关注点**：SLA 与赔付条款（别让售前口头承诺进合同附件）、数据权属与保密、验收条款与付款节奏绑定
- **法务是护栏不是敌人**：法务改条款是在保护可交付性；有异议当面聊，别在邮件里拉锯
- **红线条款直接上报**：独家绑定、无限责任、超能力处罚条款——不自行答应，升级处理（见下节）

## 6. 汇报与升级

- **升级的三个时机**：卡死超 48 小时自己无解；需要超出自己权限的资源/政策；出现风险事件（投诉/事故/舆情）
- **升级格式四件套**：事实（发生了什么）→ 影响（不处理会怎样）→ 选项（A/B/C 各自代价）→ 建议（我推荐哪个）。带问题升级扣分，带方案升级加分
- **周报/作战室纪律**：写变化不写流水（本周推进了什么/卡在哪/需要什么），让上级做选择题不做阅读理解

## 7. 跨部门摩擦的处理

- **与 BD 的目标差异**：BD 对签约金额负责，SA 对可交付与可续费负责——签约前把交付可行性与验收标准对齐，是对 BD 最大的保护
- **与产品的 feedback loop**：客户需求别只当传声筒——抽象成产品输入（多少客户、什么场景、愿意付什么价）再反馈，产品团队才买账
- **与交付的责任边界**：售前承诺 = 交付输入。方案里的每个承诺都当成写给交付同事的需求文档来写

## 8. 信息源习惯

- 以官方文档与产品发布渠道为准，二手转述的信息（含内部群截图）使用前二次核实
- 好的打法沉淀回内部知识库/技能包——对照 `enablement-influence.md`：对内赋能与对外布道是同一件事的两面
