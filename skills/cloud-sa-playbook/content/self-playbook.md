# 自身资源盘点与边界（本身情况）

打法不只取决于客户，还取决于"我们手里有什么、不能做什么"。本篇讲自身侧的三件事：资源盘点、政策用法、边界纪律。注：具体商务政策随云厂商与时期变化，此处写通行结构，落地前以内部最新政策为准（对照包级声明）。

## 1. 自身资源地图

| 资源 | 内容 | 使用纪律 |
|---|---|---|
| 产品与报价 | 公开刊例价是锚点，实际成交价在折扣空间内浮动（审批见 `internal-process.md`） | 方案里写刊例价口径，折扣在商务环节谈，别在技术交流时露底 |
| 案例库 | 同行业/同场景已交付案例是信任加速器 | 引用前确认客户授权与脱敏；没授权的案例宁可不说 |
| 专家资源 | 架构师委员会、产品专家、研发接口人 | 借力要提前约（专家排期以周计）；带方案去请教，不带问题去求救 |
| 生态伙伴 | ISV（应用层）/SI（交付）/MSP（运维托管）分工 | 客户要"交钥匙"时伙伴是前置资源不是补救资源 |
| 政策工具 | 迁移抵扣、POC 资源、赠送额度、培训认证 | 每一项都要换回对等承诺（见下节），不做无回报让步 |

## 2. 商务政策的用法：让步必须换承诺

政策是杠杆，不是让利工具。每一次让步前问自己"换回什么"：

- **迁移抵扣/POC 资源** ↔ 换签约时间线（"资源本季度有效"）或评估独家性（"双跑数据双方共享"）
- **额外折扣** ↔ 换多年期承诺、预付、或标杆案例授权（署名案例值真金白银）
- **赠送额度** ↔ 换新业务增量（存量的赠送只救急不救价）

失效信号：客户把你的让步当"本来就该有"——下一轮谈判它就成了基线。让步节奏宜"逐步收窄"（第一轮给足诚意，之后每轮递减），不要一次亮底牌。

## 3. 自身能力边界

**什么时候 call 专家**：超出产品公开文档深度（要架构决策支持）、跨产品组合方案（算力+网络+数据）、行业合规判断（金融/政务准入）、单子体量超自己主导过的最大规模。call 专家带三样：客户背景一页纸、现有方案草图、明确的问题清单——让专家做选择题不做问答题。

**什么时候该让单**：负毛利且无战略价值（非标杆非卡位）；超出合规边界（客户要求绕过监管的部署）；交付资源排期满且客户 deadline 刚性。让单不是失败，是把自己和公司的信用配置到能赢的战场上。

**SA 不承诺清单**（拍胸脯前逐条自查）：
1. 超产品标准的 SLA 与赔付（走专项商务，见 `customer-situations.md` 第 14 条）
2. 未发布产品/功能的上线时间（"在路上"只能描述不能承诺日期）
3. 数据效果类承诺（"上云后转化率提升 X%"——影响因素不在我们手里）
4. 合规结果承诺（"保证过等保"——测评是第三方的事，我们承诺的是整改措施）
5. 竞品性能贬损性对比数据（引用第三方可验证报告，不做自家实验室结论）

## 4. 自我保护：留痕纪律

- **口头协议邮件化**：会议里答应的任何条件，24 小时内纪要邮件确认（"按今天沟通，我们承诺 A，客户承诺 B"）
- **需求变更留痕**：范围蔓延时发变更确认（工作量/时间/费用三选一调整）
- **承诺范围写进方案**：方案文档里"范围与非范围"一节比架构图还重要
- **敏感信息不落盘**：客户未公开数据、内部未公开政策，不进聊天记录、不进交付文档、不进代码仓

## 5. 与成长的挂钩

本篇是防守，进攻靠能力：资源用不上往往是因为能力够不到。定期对照 `capability-model.md` 检视：专家资源认识几个、案例库能讲几个、政策边界摸清没有。
