# 竞争对标与替换防御

云不是独家生意：打单大概率同台竞技，存量客户天然是对手的进攻目标。竞争打法的两条纪律——**讲差异化不贬损友商，用可验证事实不用传闻**。

## 竞争格局与差异化定位

不同云厂商的差异化维度（SA 要能一句话说清自家定位）：

| 维度 | 差异化叙事方向 |
|---|---|
| 稳定性 | 大促级流量锤炼（电商峰值）、故障率与 SLA 历史、容灾体系 |
| AI 全栈 | 自研模型 + MaaS 平台 + 算力底座的垂直整合 |
| 生态与 ISV | 行业解决方案覆盖、伙伴体系规模、开发者社区 |
| 合规与属地 | 等保/行业监管资质、信创适配、数据驻留选项 |
| 价格 | 长约折扣、节省计划灵活性（价格战是最后手段，先打价值） |

**对标表纪律**：写能力维度与可验证事实（公开测试报告、客户实测数据、第三方评测），不写传闻与贬损措辞；对标表可能被客户转给对手，按"敢被对方看到"的标准写。

## 替换打法（策反友商客户）

**切入点优先级**（从易到难）：

1. 新业务/新场景：新系统不背历史包袱，先拿新场景进场，站稳后扩存量
2. 痛点事件：对手涨价、重大故障、服务降级、关键产品停止迭代——窗口期短，动作要快
3. 成本重构：客户对成本不满时，用 TCO 对比 + 迁移方案切入（注意：仅靠低价抢来的客户会被更低价格抢走，要绑定架构与迁移价值）
4. AI 切换：AI 场景是新变量，历史绑定最弱（见 `ai-solutions.md`）

**替换项目的特殊打法**：POC 权重更高（客户要证据）；迁移成本是客户最大顾虑——把迁移方案（工具、时长、停机窗口、回滚）做成方案核心章节而不是附录；双边云并行期方案（过渡期双跑）降低决策心理门槛。

## 存量防御

- **护城河建设**：深度托管服务渗透（托管服务用得越多迁移成本越高）、数据与工作流绑定（数据仓库/中间件/CI-CD 链路）、联合创新项目（客户投入了设计精力就不会轻易推翻）。
- **预警雷达**：对手 POC 传闻、客户突然索取完整资源清单与架构文档（迁移评估前兆）、异常的成本审计要求——出现即启动保卫（见 `account-deepening.md` 流失预警）。
- **主动进攻性防御**：在对手强势场景（如某产品线）提前给客户替代方案与成本对比，不让对手的方案先落纸面。
- **高管关系**：技术绑定挡得住技术评审，挡不住组织决策——战略客户必须有高层技术汇报机制。

## 竞争情报纪律

- 合规来源：公开资料（财报、招标公告、白皮书）、客户交流中的合法信息、行业会议
- 红线：不挖对手员工套内部报价、不诱导客户泄露保密标书、不传播对手未经证实的负面消息
- 用法：竞争信息进商机作战室统一分析（见 `iron-triangle.md`），不单线行动

## 关键话术

- 不说对手差，说我们不同：贬损友商抬高的是对方的可信度。
- 替换单赢在迁移方案：客户怕的不是对手不好，是搬家搬出事故。
- 防御的最佳时机是没有被进攻时：护城河（托管渗透 + 数据绑定 + 联合创新）在日常巡检里悄悄修筑。
- 窗口期思维：对手的故障与涨价是稀缺资源，24 小时内必须让客户看到我方的方案。
