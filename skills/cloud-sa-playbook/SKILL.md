# 云 SA 获客与打单 Playbook

SA 的核心姿势是"用技术换信任，用方案换订单"——不做低效陌拜，靠平台线索 + 铁三角协同。按问题类型选择知识文档：

| 场景 / 问题 | 用哪份 |
|---|---|
| SA 客户从哪来：四类获客渠道、线索路由链路、商机优先级怎么排 | `content/acquisition-channels.md` |
| 铁三角各角色分工、单子全生命周期怎么配合、常见摩擦怎么解 | `content/iron-triangle.md` |

工作方式：

1. **获客策略**：用渠道四象限（市场线索 / 销售协同 / 生态伙伴 / 内容影响力）判断客户从哪来；优先经营存量深耕与伙伴借力，不做扫楼冷 Call，技术型触达（社区痛点精准联系、行业会技术高管交流）除外。
2. **商机推进**：按线索路由链路定位商机在哪一跳（MQL → SQL → 归属路由 → SA 立项），用优先级四因子（存量 / 质量 / 复杂度 / 竞争）决定 SA 投入深度；SA 有挑单权，无预算纯比价的单不占坑。
3. **打单协同**：铁三角按五段时间线分工——BD 开门收口、SA 技术成交、交付落地；节奏冲突靠商机分级机制调和，利益对齐点在"客户消费增量"而非"签单"。
4. 所有产出物（获客计划、商机作战卡、协同复盘）统一用 `export_deliverable` 打包交付。

注：云厂商内部具体分配规则（系统、评分项）不对外公开且随团队/时期变化，本包是公开资料（SA 岗位 JD、阿里云合作伙伴门户权益）+ 云行业通行做法的合成，结构性准确，细节需结合实际校准。

深度知识正文见 `content/`，回答客户/团队问题或写打法文档时直接引用其中的表格与框架，不要凭记忆复述。
