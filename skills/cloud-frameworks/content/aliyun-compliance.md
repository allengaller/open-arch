# 阿里云安全合规体系全景（等保 / 密评 / 数据安全 / 认证）

> 全网调研档案（第三轮，采集于 2026-10-28）：金融/政企售前的"合规怎么落"主题底座——责任共担、等保 2.0 分工、配置审计合规包全列、密评、数据安全、合规认证清单、行业监管映射、云安全中心版本矩阵。与 `aliyun-landing-zone-official.md` §3.4/§7（LZ 防护规则与安全基线）、`well-architected.md`（安全支柱评审）配套使用。

## 1. 责任共担模型

- 官方定义原文（[安全责任模型](https://help.aliyun.com/zh/acsg/security-responsibility-model)）："基于阿里云的客户应用，其安全责任由双方共同承担：阿里云要保障云平台自身安全并提供安全产品和能力给云上客户，客户负责基于阿里云服务构建的应用系统的安全。"
- **阿里云侧**：数据中心/骨干网的物理与硬件安全；飞天之上的**虚拟化层和云产品层**安全；平台侧身份管理、监控运营。
- **客户侧**：以安全方式**配置和使用**云产品，基于云产品安全能力构建应用（安全组、AK、应用漏洞、数据安全归客户）。
- **2024 升级**：《阿里云安全白皮书（2024 版）》从"责任共担"升级为"**云上安全共同体**"——云平台主动提供保障措施帮客户"安全地使用云"（例：AK 泄露 GitHub 联动限制性保护+轮转机制）；客户仍是"业务第一安全责任人"。（[白皮书 PDF](https://security-help-center.oss-cn-hangzhou.aliyuncs.com/%E9%98%BF%E9%87%8C%E4%BA%91%E5%AE%89%E5%85%A8%E7%99%BD%E7%9A%AE%E4%B9%A6%EF%BC%882024%E7%89%88%EF%BC%89.pdf)）
- **售前一句话**：云平台底座（机房/硬件/虚拟化/云产品自身）事故归阿里云；客户配置不当（安全组全开、AK 泄露、应用漏洞）归客户。

## 2. 等保 2.0：云平台与客户的分工

- **核心口径**（[电子政务云文档](https://help.aliyun.com/document_detail/93371.html)）："阿里云电子政务云平台及阿里云产品的安全性、等保合规性由阿里云提供（相关资质证明可通过工单申请），业务的安全合规性需要您采购安全产品进行保障。"配置审计产品页明确："**2019 年 12 月起，企业在云上的 IT 系统需要单独经受等保 2.0 的测评**"——**平台过等保 ≠ 租户系统过等保**。
- **平台侧资质**（历史公开口径，现行范围以工单索取资质为准）：公共云等五大系统**等保三级**；金融云平台与电子政务云平台**等保四级**；电子政务云另通过**中央网信办云计算服务安全评估（增强级）**。
- **客户侧支撑能力**：
  1. 配置审计**等保预检（免费）**：等保 2.0 条款→云上配置检测规则，可下载预检报告呈递测评机构；有等保二级/三级预检合规包；
  2. 云安全中心**等保合规检查**：覆盖通信网络/区域边界/计算环境/管理中心，控制台可申请"等保 2.0 解决方案材料包"（含平台等保备案证明、测评报告、《公共云等保合规白皮书 2.0》）；
  3. 基线加固：云安全中心应答等保二级主机安全 15+ 要求项；Alibaba Cloud Linux 提供"等保 2.0 三级版镜像"；
  4. LZ 落地：合规包 + 多账号集中治理把等保红线固化为持续合规（[LZ 合规管理方法](https://help.aliyun.com/zh/landing-zone/solution-78)）。
- **售前一句话**：平台资质只证明"云本身"合规；定级备案和整改的主体责任在客户，阿里云给证明材料、预检工具与基线产品。

## 4. 密评（商用密码应用安全性评估）

- **强制对象**：关键信息基础设施、**等保三级及以上**系统须通过密评方可投入运行，运行后**每年至少一次**。（依据《密码法》、GB/T 39786-2021）
- **平台资质（核心卖点）**：2019 年**专有云（Apsara Stack）国内首家通过云平台密评**（三级）；2023-10 **公共云平台国内首家通过密评三级**——"云上应用开展密评时，**可复用平台密评的部分测评结论**"（如物理和环境安全部分直接复用公共云平台密评报告）；飞天企业版已服务 50+ 政金电力能源客户。
- **密码产品矩阵**：**加密服务**（虚拟密码机，国密局检测认证 GM/T 系列，非中国内地 FIPS 140-2 L3；EVSM 支持 SM1/2/3/4+PBOC；密钥完全由客户掌握）、**KMS**（国密局认证/FIPS 托管密码机、BYOK/KYOK、凭据管家、90+ 云产品集成）、**密评咨询服务**（差距分析→方案设计→整改→测评→备案五步）。
- **行业规范**：政务 2024-04 政务云平台/应用密评实施指南；医疗 2023-12 卫健委密评规范（云平台/全民健康信息系统/医疗机构）。
- **售前一句话**：物理环境与平台底座的密码整改阿里云已完成并持三级密评报告，客户应用可复用平台结论，只需聚焦应用与数据层国密改造。

## 5. 数据安全合规（数安法/个保法映射）

- **主线产品**：**数据安全中心 DSC**（2021-01 由"敏感数据保护 SDDP"更名）：满足等保 2.0"安全审计"与"个人信息保护"要求，提供敏感数据识别、分类分级、审计、脱敏、异常检测；扫描 MaxCompute/OSS/RDS/PolarDB/OceanBase 及自建库；有免费版；仅识别打标不保存数据。
- **分类分级**：S1~S4 四级；内置**行业模板**（金融、能源、汽车等），依据 GB/T 35273、《JR/T 0197-2020 金融数据安全分级指南》、《JR/T 0171-2020 个人金融信息保护技术规范》等。
- **数据出境**：三条路径（安全评估/标准合同/保护认证），重要数据从严；阿里云官方"跨境数据合规方案"独立产品页**待核实**（售前引用前向阿里云确认最新材料）。
- **方法论与认证**：DSMM 数据安全能力成熟度模型（GB/T 37988-2019，阿里巴巴牵头起草，六生命周期×四维度×5 级）+ 阿里云 DSMM 评估/整改咨询；《云上数字政府之数据安全建设指南》（2022-09）。
- **售前一句话**：开通 DSC→行业模板全量扫描→输出 S1-S4 敏感数据资产目录→挂接脱敏/加密/审计策略；金融客户直接套 JR/T 0197/0171 模板。

## 7. 行业监管映射

### 7.1 金融
- 金融云按人民银行/银保监标准建设：JR/T 0166/0167/0168-2020（技术架构/安全/容灾）+ 机房测评、等保测评指南、灾难恢复、网上银行规范、业务连续性监管指引、外包风险监管、证券期货等保要求等（[金融云特性](https://help.aliyun.com/zh/document_detail/29851.html)）；**独立机房集群**（如华东1金融云杭州），与公共云资源不混用。
- JR/T 0071.2-2020（金融等保实施指引，含云计算部分）：第三方综述口径，引用注意；JR/T 0171/0197 与 DSC/DataWorks 分类分级联动。
- 配置审计侧基线：RMiT、PCI-DSS、数据库合规最佳实践。

### 7.2 政务
电子政务云：党政机关/事业单位/国央企定制，**网信办安全评估增强级**、GB/T 31168 增强级、**等保四级**、《政务云解决方案评估》可信认证、连续多年入围中央国家机关政采目录；与公共云完全物理隔离，可承载非涉密敏感信息与重要政务业务；全链路加密/审计、国密。

### 7.3 医疗
中国 GMP 附录《计算机化系统》合规包 + 卫健委医疗行业密评规范（2023-12）+ GxP 欧盟附录 11 合规包与医疗 GxP 蓝图（LZ 五蓝图之一）；其余卫健规范的官方映射待核实。
